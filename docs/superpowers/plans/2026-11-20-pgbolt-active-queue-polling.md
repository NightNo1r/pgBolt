# PgBolt 7b-2. План реализации опроса активной очереди

> **Для исполнения:** пройти задачи по порядку с `superpowers:executing-plans` или `superpowers:subagent-driven-development`. Шаги отмечены `- [ ]`.

**Цель** — сохранить срок планового опроса очереди после пустой досрочной выборки по освобождению слота и подтвердить SLO 1–6 на профиле B.

**Архитектура.** Сроком владеет `Dispatcher.QueueState` каждой очереди. Диспетчер сохраняет срок при обработке сигнала и решает, как назначить следующую выборку, когда получает ответ PostgreSQL.

**Стек.** .NET 10, xUnit, `FakeTimeProvider`, PostgreSQL 17, PgBouncer в режиме транзакций. [Одобренная спецификация](../specs/2026-11-20-pgbolt-active-queue-polling-design.md)

**Итог исполнения.** Исправление реализовано и проверено. На десятиминутном прогоне через PgBouncer нарушены SLO 1, 2 и 4. Приёмка остаётся открытой. [Отчёты и замеры](../../performance.md#проверка-опроса-активной-очереди-20-ноября-2026)

## Global Constraints

- Опрос пустой очереди использует действующие `MinPollInterval`, `MaxPollInterval` и jitter. Сигнал enqueue сбрасывает интервал. При исчерпанном кластерном лимите место становится доступно после коммита исхода.
- Профиль B задаёт 10 000 задач/с, ≥ 95 % потока в каждом окне 10 с, p50 ≤ 50 мс, p99 ≤ 500 мс, p99.9 ≤ 2 с. Сценарий проверяет полный набор SLO отдельно для обоих подключений. [Профиль и пороги](../../performance.md)

## Review Focus

| Условие | Что проверить в задаче 1 |
|---|---|
| Два слота освобождаются до срока опроса | Обе досрочные выборки сохраняют исходный срок данной очереди |
| Срок наступил ровно к началу запроса | Пустой ответ увеличивает интервал один раз |
| Досрочный запрос завершился после срока | Плановый опрос уже готов к запуску |
| Вместе с освобождением слота пришёл enqueue | Срабатывает обычный сброс интервала |
| Досрочный запрос вернул `LimitReached` | Действуют правила лимита, досрочный повтор разрешает `OnLeaseFreed` |

### Задача 1. Исправить планирование опроса

**Файлы.** `src/PgBolt.Server/Runtime/Dispatcher.cs` и `tests/PgBolt.Server.Tests/Unit/DispatcherTests.cs`. Входы — существующие `OnSlotFreed(string queue)`, сигнал enqueue, результат `FetchAsync` и монотонные часы. Результат наблюдаем через время вызовов dequeue в тестовой очереди `_dequeues`.

- [x] Добавить регрессионный тест `SlotPollKeepsDeadline`. Первая частичная выборка при четырёх воркерах возвращает две задачи. Освободить их слоты на 10-й и 20-й мс, каждый раз дождаться пустой выборки и перехода диспетчера в ожидание. При тестовом jitter ×1 и минимуме 50 мс ожидаемые отметки вызовов — `[0, 10, 20, 50, 150]`. На 49-й и 149-й мс проверить число вызовов перед продвижением часов ещё на 1 мс.
- [x] Запустить `dotnet test tests/PgBolt.Server.Tests -c Release --filter 'FullyQualifiedName~SlotPollKeepsDeadline'`. На исходной версии выборка на 50-й мс пропущена.
- [x] В `ApplyFlags()` перед первым переносом `NextPoll` по освобождению слота запомнить прежний срок в `long? PollBeforeSlot` у соответствующей очереди. Повторный сигнал сохраняет первоначальное значение. При сигнале enqueue сбросить его и применить обычное пробуждение. В `RunAsync()` забрать и очистить сохранённый срок при старте каждого fetch, включая попытку, которая завершится ошибкой.
- [x] Восстановить срок только для пустого результата при свободном кластерном лимите и условии `fetchStartedAt < deadline`. Для остальных результатов использовать существующие правила диспетчера. Просроченный за время запроса срок даёт нулевую паузу через `NextPollDelay()`.
- [x] Дополнить тесты граничными случаями из Review Focus. При начале пустой выборки ровно на 50-й мс следующая положена на 150-й. Для запроса с 40-й по 60-ю мс следующий начинается на 60-й. Для одновременных сигналов на 10-й мс после пустой выборки следующий срок — 110 мс. При новом `LimitReached` на 10-й мс прежний срок 50 мс пропускается, а `OnLeaseFreed` на 70-й мс разрешает запрос сразу. Использовать существующие `Respond`, `RespondLimited` и `Idle`. Совпадающие сигналы подавать во время одного управляемого запроса, пока цикл не может их обработать по отдельности.
- [x] Запустить `dotnet test tests/PgBolt.Server.Tests -c Release --filter 'FullyQualifiedName~Unit.DispatcherTests'` и затем `dotnet test PgBolt.slnx -c Release --filter 'Category!=Load'`. Оба прогона должны пройти до начала измерений. Сохранить исправление и тесты одним коммитом.
